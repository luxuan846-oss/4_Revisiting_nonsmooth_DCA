# Booming 模块细则

SKILL.md 给出原则、路由与阶段交付；本文件给出 M1–M4 的步骤和四个出口的模板。

---

## M1 选题研讨（核心）

**输入**：一句话问题，或 M2 / M3 产出的候选问题。

**起点**：沿用上下文中的研究目标、材料、用户积累和目标 venue。按 SKILL.md 的协作方式共同构造问题；助手可主动贡献第 3、4 问的候选洞察，并说明来源与依据。目标 venue 未定时先讨论目标领域的贡献。

**研讨线索**：每轮聚焦一个问题，顺序按材料调整。已有证据能回答的内容直接判断。出口 A 之前相关问题应有答案或明确的"待验证"。


| 序号 | 追问 | 对应原则 | 写入交付的哪一节 | 答不上来时 |
|---|---|---|---|---|
| 1 | 合理预期的最好结果，相比最接近的工作，增加什么值得领域关注的认识或能力？怎样使问题更有价值？ | C1 | 研究背景 | 核对已有工作，主动提出更有价值的问题表述 |
| 2 | 当前切入依据是什么？未来为什么值得研究，会留下什么方法与认识？ | C2 | 研究背景（为什么现在） | 提出有依据的候选解释，未确认部分记为"待验证" |
| 3 | 发现了什么关系、机制或解法？它增加什么理解，能产生什么可检验后果？ | C3 | 研究动机 | 助手提出候选洞察，结合材料与用户共同深化 |
| 4 | 切入点来自哪里，独立判断的依据是什么，与已有解释有何不同？ | C5 | 研究动机（切入点） | 比较具体观察与已有解释 |
| 5 | 参照目标领域的优秀工作，哪项结果最能提升贡献，证据需要做到什么程度？主难点在哪里？ | C4 | 科学问题（已知 / 未知表、主难点） | 提出具体的成果提升方案；按需使用 T1、T2 |
| 6 | 最可能的失败方式是什么？ | — | 风险与第一步 | 给出一个具体的失败情形 |
| 7 | 能验证想法的最小一步是什么？ | — | 风险与第一步 | 给出一个一到两周内能完成的动作 |

七问覆盖 C1–C5 五个坐标；工具箱 T1–T5 不单独占问，只在某一问的回答需要时使用。

**判定规则**：

- **投入**：预期贡献有具体价值，切入点有依据，有值得尝试的推进方法。说明推荐理由与探索空间。
- **待验证**：方向有吸引力，关键认识尚未确认；给出最值得先做的一项推导、实验或查证。
- **放弃**：有明确证据表明预期贡献已被覆盖，或关键构造不可行且没有值得推进的调整。说明对象和依据；缺少共识或设想尚未成熟不单独作为放弃理由。

## M2 拆假设

**输入**：一篇论文（arXiv ID、PDF、标题），或用户自己的草稿目录。

### 他人论文

1. 读摘要、主定理、假设一节。
2. 列出全部假设与目标定义（驻点判据、复杂度度量、算法类、参数条件）。
3. 每项标注：
   - **必要**：有下界、反例或已知的不可能性结果；
   - **可能放宽**：指出条件的使用位置和作用，并提供支持替代论证的依据；仅使用一次不足以判定可删除；
   - **未知**。
4. 将有实质研究价值的限制、机制或未解释现象转成 M1 候选问题。

### 草稿模式

1. **先列全成果（T5）**：读摘要、贡献列表、全部 theorem / corollary / lemma 环境和附录标题，填成果结构表。
2. **分析适用限制（T2，贡献是界或条件时才做）**：用户的哪些结论只在某个限制下证明了（例如常数步长、特定初值、特定驻点判据）？对每项写出最便宜的逃逸路线，并定位证明中阻止推广的那一步（文件与行号）。
3. **叙事对齐（T4）**：标题、摘要、贡献列表强调的点，与成果结构表的重心是否一致？审稿人最可能怎样曲解标题？
4. **深化成果**：指出当前最有价值的发现，推荐一项最能提升工作的推进动作，并给出初步思路。按研究类型选择关键推导、反例、实验或方法构造；已有结果充分时再优化表达。
5. 默认只读草稿，推进方案写在出口 B；用户授权修改时按其要求执行。

## M3 可解性扫描

**输入**：一个研究方向。


1. 结合用户积累、经典与近期文献，寻找重要开放问题及有依据但尚未充分认识的问题，不局限于当前项目。
2. 寻找可用工具、现象、数据、结构和新的问题表述，包括相邻领域；也考虑已有工具的新用途。
3. 提出具体切入点，说明为何值得尝试、当前从哪里开始，以及成果可能为领域和后续研究留下什么。
4. 对排名前列的交叉点，按 SKILL.md「最接近已有工作的查证」确认是否已有人做过。
5. 给出明确推荐及理由；每个交叉点附可核实文献，无法核实的标"待核对"。后续价值可以体现为方法、认识或新问题。

## M4 判断日志

每个出口交付后，向 `~/.Codex/booming/judgment-log.md` 追加一条：

```markdown
## <YYYY-MM-DD> <议题短名>
- 入口：想法 / 论文 / 草稿 / 方向
- 判断：初步问题（A0） / 投入 / 待验证 / 放弃 / 草稿体检 / 方向扫描
- 我看到了什么：……
- 为什么现在可解：……
- 预言（可证伪）：如果判断对，到 <日期> 应当看到……
- 已关闭分支：……（理由）
- taste 规则（若本次提炼出新的）：……
- 白板：whiteboards/<文件名>
- 回看：后续追加回看记录，注明本条日期与议题，保留原判断。
```

**回看**：用户要求回看，或开始新议题时发现有到期预言，结合已有结果追加兑现情况、原因与判断修正；只询问缺失的信息。通过持续回看和具体反馈积累判断经验。

## 出口模板

### 出口 A0 初步科学问题

讨论形成明确问题后交付的核心文档，分研究背景、研究动机、科学问题、风险与第一步四节；用户可直接拿去给导师或合作者。写入项目目录（例如 `research/`），白板只记路径。

```markdown
# <题目>：研究背景、动机与科学问题

## 1. 研究背景（第 1、2 问：C1、C2）
- 对象：<算法、问题类、参数范围、噪声或数据模型，附原文位置>
- 已有结果：<正面结果及其条件，附出处>
- 为什么现在可解：<具体切入依据>

## 2. 研究动机（第 3、4 问：C3、C5）
- 看到了什么：<两三句话，附支撑它的例子或计算>
- 对领域的意义：<谁会改变哪个判断或做法（C3）>
- 切入点来源：<独立观察、已有积累或新的联系，说明依据（C5）>

## 3. 科学问题（第 5 问：C4）
- 主问题：<一句话，写到能被反例否定的程度>
- 已知 / 未知表：<每种情形的结论与依据；未知格单独标出>
- 子问题：<基础、主问题、边界，各标"已推导 / 待证">
- 主难点：<一个尚未解决的步骤>

## 4. 风险与第一步（第 6、7 问）
- 风险：……
- 第一步：<一到两周内的动作>

补证清单：<判为"待验证"的问题及补证动作>
```
